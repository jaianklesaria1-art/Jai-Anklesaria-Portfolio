Executive Summary

This report covers a WCAG 2.2 Level AA audit of two pages on hercessihcp.com: the homepage and the Patient Support registration page. Ten findings were verified against the live DOM, keyboard behavior, and computed styles, not visual inspection alone. One finding sits outside WCAG's scope entirely: the site's only call-to-action button is non-functional on every page, which blocks the site's core task for all users regardless of ability.

Seven checks passed outright and are listed in the Conformance Notes section, so this reads as a balanced assessment, not a one-sided list of defects.

Scope & Methodology

Two pages were audited: the homepage and the Patient Support registration page. Every finding is verified, not eyeballed. Six checks were run, in order:

  • Task completion test: set one real goal, place an order, and attempted it exactly as a visitor would, mouse first, then keyboard only, with the console open for hidden script errors.
  • Keyboard only pass: tabbed through the entry gate and main navigation with no mouse.
  • Disclosure check: for every dropdown, compared the submenu's computed display before and after moving real keyboard focus to its trigger, not just a mouse hover.
  • Computed style inspection: read getComputedStyle(document.activeElement) after each Tab press, so a missing focus ring is a measured fact, not an impression.
  • DOM queries: counted images without alt text, mapped the full heading sequence, and checked every form field for a linked <label>.
  • Contrast and target size: calculated contrast ratios directly from computed RGB values using the WCAG relative luminance formula, and measured tap targets with getBoundingClientRect().

One boundary was held throughout: the site's real Patient Support form was not submitted. Doing so would have pushed fake data into a live business system that isn't mine to test that way, and that requires authorization I don't have.

Findings

F-01Primary call to action is non-functionalCritical
WCAGFunctional, no WCAG mapping LocationEvery page, main navigation

Every page carries an "Order Now" button in the same position, styled identically to a working call to action. Clicking it with a mouse produces no result. Tabbing to it and pressing Enter produces no result. The browser console shows no script error. The link's href is a literal # on every page, with no click handler attached. It was never connected to anything.

1
Exhibit A · hercessihcp.com, every page

href="#", no click handler, nothing in the console.

Recommendation: wire the button to the real ordering flow, or remove it from the page until that flow exists.

F-02Entry gate suppresses its own focus indicatorHigh
WCAG2.4.7 Focus Visible, AA LocationEntry gate modal, all pages

The site opens behind an "Are you a healthcare professional?" modal. Tabbing to the Yes button moves focus there, confirmed via the DOM, but nothing is visible on screen. outline-style is explicitly set to none, even though a color and width are still defined underneath it.

2
Exhibit B · hercessihcp.com entry gate

Focus is on "Yes" here. No ring, no border change, nothing a keyboard user can see.

Recommendation: restore outline: 2px solid #2F2F2F on :focus-visible. Color and width were already defined, only the style was disabled.

F-03Registration form has no field labelsHigh
WCAG3.3.2 Labels or Instructions, A LocationPatient Support registration form

The Patient Support page carries a real seven field form: name, business email, ZIP, profession, organization, and request type. Every field is labeled with placeholder text only. Placeholder text disappears the moment someone starts typing, so a user who pauses mid form loses the one thing telling them what the field was for.

3
Exhibit C · AccordCares registration form

Seven fields, zero <label> elements. Placeholder is standing in as the only instruction.

Recommendation: add persistent visible <label for> elements for every field. Keep placeholder text as a supplementary hint only, never the sole label.

Prioritization

Findings are grouped by impact against effort to fix, not severity alone, so the order reflects what's worth doing first.

Fix first, low effort

  • Restore the focus outline on the entry gate (F-02), a one-line CSS fix
  • Move the skip link ahead of the cookie widget
  • Add alt text to the 5 missing images
  • Add text or aria-label to the 2 empty links
  • Fix the heading hierarchy skip

Fix next, higher effort

  • Wire up the Order Now button (F-01), highest impact on the site, requires the actual ordering integration
  • Add real labels to the registration form (F-03)
  • Rebuild the Ordering Details dropdown as a keyboard-operable disclosure
  • Convert the gate buttons from links to real buttons

Remediation & Handoff Format

The three highest-severity findings are written below in the format I'd hand to an engineering team: steps to reproduce, the fix, and acceptance criteria. This is the format I would use for a handoff, it was not filed as an actual ticket with Accord BioPharma or Asentech.

TICKET F-01Order Now button has no destination
Steps to reproduce
  1. Open any page on hercessihcp.com
  2. Click, tap, or keyboard-activate the "Order Now" button
  3. Observe: no navigation, no modal, no console error
Fix

Point the href at the real ordering flow, or attach the intended click handler. If the flow doesn't exist yet, remove the button or replace it with a working contact path until it does.

Acceptance criteria
  • Clicking "Order Now" on every page navigates to a real ordering destination
  • The same result is reachable by keyboard (Tab + Enter)
  • No console errors on activation
TICKET F-02No visible focus state on entry gate
Steps to reproduce
  1. Load hercessihcp.com
  2. Press Tab until focus reaches the "Yes" or "No" button on the gate modal
  3. Observe: no visible ring, border, or shadow change
Fix

Set outline: 2px solid #2F2F2F; outline-offset: 2px on :focus-visible for both buttons.

Acceptance criteria
  • Tabbing to either button shows a visible, high-contrast focus indicator
  • Indicator meets 3:1 contrast against the surrounding background
TICKET F-03Registration form fields have no labels
Steps to reproduce
  1. Open the Patient Support page
  2. Inspect any form field
  3. Observe: no <label>, no aria-label, placeholder text only
Fix

Add a visible <label for="field-id"> for each of the seven fields. Keep placeholder text as a secondary hint, not the only instruction.

Acceptance criteria
  • Every field has a persistent visible label, on screen before and during input
  • Each label is programmatically associated via for/id

Conformance Notes

Seven checks passed outright, listed here so this reads as a balanced assessment:

3.1.1  <html lang="en-US"> is set correctly site wide.
1.3.1  All four landmark regions are present: main, nav, banner, and contentinfo.
2.4.2  Page titles are descriptive and unique on every page checked, not a repeated template string.
1.4.3  Entry gate button text contrast measures 8.81:1, well past the 4.5:1 AA minimum.
2.5.8  Entry gate button target size measures 93 by 29px, past the 24 by 24 AA minimum.
1.4.3  Boxed warning body text contrast measures 13.39:1.
1.4.3  Main nav links and the "Contact a Rep" tab both measure 13.39:1 too, the contrast holds outside the gate modal.

Appendix & Notes

  • A criterion-by-criterion pass alone would have caught F-02 and F-03. It would not have caught F-01, there is no WCAG line item for "the main call to action does nothing." That was only found by attempting the real task end to end.
  • Every number in this report came from the live DOM: getComputedStyle, getBoundingClientRect, a real click, and a check of what happened after. Nothing was estimated by eye.
  • The skip link on the homepage exists but sits behind seventeen other tab stops before it, which fails its purpose as completely as no skip link at all. That's only visible by tabbing through it directly, not by confirming the element exists in the DOM.
  • The site's real Patient Support form was not submitted during this audit, to avoid sending fabricated data into a production system that isn't mine to test that way.
